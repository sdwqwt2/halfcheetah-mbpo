# MBPO on HalfCheetah-v5 — Group 18

PyTorch implementation of **Model-Based Policy Optimization** (Janner et al., NeurIPS 2019) for
Gymnasium's MuJoCo `HalfCheetah-v5`, with a model-free **SAC** baseline from the same code.

Team: Azamat Kharisov, Alexander Kurilenko, Egor Novokreshchenov, Ivan Prikhodko, Maxim Izyumov.

## Quick start on Kaggle (training)

1. Upload `notebooks/MBPO_HalfCheetah_Kaggle.ipynb` to Kaggle (*Create → New Notebook → File → Import Notebook*).
2. Settings: **Accelerator → GPU T4 x2**, **Internet → On**.
3. **Save Version → Save & Run All (Commit)**. It runs in the background, and you can close the browser.
4. After it finishes (about 11.5 h), download `mbpo_results.zip` from the version's **Output** tab.

The notebook is self-contained. Every source file below is written to disk by a readable `%%writefile`
cell, so nothing else needs uploading. It runs **MBPO seed 0 on GPU 0**, **MBPO seed 1 on GPU 1**, and the
**SAC baseline** on GPU 0. Each run stops itself after `TRAIN_HOURS` (default 11). After that, the notebook
plots the learning curves, evaluates the policies on 10 episodes, records videos (random policy vs trained
MBPO vs SAC), and zips everything.

For a 3-minute dry run, set `SMOKE_TEST = True` in the settings cell.

## The small worked example (for the submission)

`notebooks/MBPO_Walkthrough.ipynb` runs on a CPU in under a minute and shows, with printed numbers:
fitting the probabilistic ensemble (Gaussian NLL), one branched model rollout, and **one SAC update step
by step** (soft Bellman target → critic update, reparameterised actor update, temperature update, Polyak
target update). It ends with the full MBPO loop on a toy 1-D "cheetah" against model-free SAC.
If `results/` from the Kaggle run is placed next to it, it also shows the HalfCheetah curves.

## Layout

```
mbpo/
  config.py         hyper-parameters (paper defaults) + presets: mbpo / sac / smoke
  networks.py       batched ensemble layers, twin Q, tanh-Gaussian actor
  replay_buffer.py  GPU-resident FIFO buffer (D_env and D_model)
  sac.py            Soft Actor-Critic with automatic temperature
  dynamics.py       probabilistic ensemble p(s', r | s, a): NLL training, bootstrap, holdout, elites
  trainer.py        the MBPO loop, evaluation, checkpoints, logging
train.py            CLI:  python train.py --algo mbpo --seed 0 --time-budget-hours 11
record_video.py     MUJOCO_GL=egl python record_video.py --checkpoint runs/mbpo_seed0/best.pt
plot_results.py     learning curves + results table from runs/*/progress.csv
notebooks/
  MBPO_HalfCheetah_Kaggle.ipynb   generated by tools/build_kaggle_notebook.py
  MBPO_Walkthrough.ipynb          generated by tools/build_walkthrough_notebook.py
```

After editing any `.py` file, regenerate the Kaggle notebook with `python tools/build_kaggle_notebook.py`.

## Run locally

```bash
pip install -r requirements.txt
python train.py --algo mbpo --smoke          # ~1 min sanity check
python train.py --algo mbpo --seed 0         # full run (GPU strongly recommended)
python train.py --algo sac  --seed 0         # model-free baseline
python plot_results.py --runs runs --out results
tensorboard --logdir runs
```

Any config field can be overridden, e.g. `--set rollout_schedule=[20,100,1,5] --set ensemble_size=5`.
This is how to run the rollout-horizon and ensemble-size ablations from our proposal.

## Algorithm and hyper-parameters

Each epoch has 1000 real environment steps. Every 250 steps, the ensemble is retrained on all real data
and 100k one-step branched rollouts are generated from real states. After every real step, the agent
does G SAC updates on batches of 5% real and 95% model data.

| parameter | ours | MBPO paper (HalfCheetah) |
|---|---|---|
| ensemble / elites | 7 / 5, 4×200 swish, Gaussian output | same |
| model training | NLL, bootstrap, 20% holdout (max 5k), early stop after 5 epochs w/o 1% gain | same |
| model retrain frequency | every 250 env steps | same |
| rollouts | 100k start states, length k = 1, retain 1 epoch | same |
| real data ratio | 0.05 | same |
| SAC | 2×256, lr 3e-4, γ 0.99, τ 5e-3, batch 256, target entropy −3 | same |
| **SAC updates per env step G** | **20** | 40 |
| initial random steps | 5000 | 5000 |
| env steps | up to 400k, or until the 11 h budget runs out | 400k |

G = 20 is the only deliberate change. It halves the SAC compute so a run fits in one 12-hour Kaggle session.
One difference in model training: we restore each member's best-holdout weights after early stopping.

**Logged per epoch** (`runs/<run>/progress.csv` and TensorBoard): evaluation return, training-episode return,
critic/actor/alpha losses, α, entropy, mean Q, model holdout MSE, model one-step MSE on the latest real data,
model train time/epochs, rollout reward, buffer sizes, wall time.
